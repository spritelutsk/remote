# Фронтенд-разработчик SpriteNote

Ты правишь SPA личного «проводника» для заметок. Сборки нет: файл из `public/` уходит
в браузер как есть, проверка — перезагрузка страницы.

Перед работой прочитай `docs/frontend.md`.

## Устройство

- `public/index.html` — вся разметка, включая модалки и вкладки
- `public/css/style.css` — единственный файл стилей
- `public/js/app.js` — приложение целиком: один IIFE, объект `state`, полная перерисовка
- `public/vendor/xterm/` — xterm.js положен локально, не из CDN

Ключевые места в `app.js`: `DEFAULT_SETTINGS`, `state`, `ERROR_MESSAGES`, `api()`, `ICONS`,
семейство `render*()`. Данные приходят одним плоским списком из `GET /api/nodes`;
иерархия, хлебные крошки и поиск считаются в браузере.

## Правила, которые легко нарушить

1. **Пользовательский текст в `innerHTML` — только через `renderMarkdown()`**, и только в его
   порядке: сначала экранируется весь исходник, потом расставляются теги. Схемы ссылок — по
   белому списку (`http`, `https`, `mailto`). Это единственное место, где текст пользователя
   становится разметкой; поменяешь порядок — получишь XSS на собственных заметках.
2. **Никаких emoji в интерфейсе.** На целевой Linux-машине эмодзи-шрифта нет, они рисуются
   пустыми квадратиками. Иконка — новый inline-SVG в `ICONS`.
3. **Не вводи сборщик, TypeScript, фреймворк и npm-зависимости фронтенда.** Это осознанный
   выбор проекта: «залил файл — обновилось» ценнее удобств сборки.
4. **Новый код ошибки с сервера — новая строка в `ERROR_MESSAGES`.** Без неё пользователь
   видит «Произошла ошибка».
5. **`DEFAULT_SETTINGS` — ручное зеркало `SETTINGS_SPEC`** из `server/user-settings.js`.
   Меняется одно — синхронизируй второе.
6. **Вкладка «Инструкция» (`#view-help`) — статическая разметка в `index.html`.**
   Поменял интерфейс — обнови её руками, рассинхрон ничем не ловится.
7. **Настройки пользователя живут на аккаунте, а не в `localStorage`.**
8. **Цвета, размеры, радиусы и тени — только переменными из `:root`** в начале `style.css`.
   Цветовой литерал в правиле ниже — ошибка. Цветов в палитре четыре — синий, зелёный, жёлтый,
   красный (`--c-*` с оттенками `-ink`, `-soft`, `-wash`, `-line` — от мелкого текста до заливки
   целой карточки); пятый оттенок не заводим, новая цветная сущность берёт один из четырёх. Исключений три, и они прокомментированы на месте:
   лупа в поиске (data-URI), фон терминала (дублируется в теме xterm в `app.js` и обязан
   совпадать) и SVG-иллюстрация лендинга.
9. **Фокус виден.** Единственное правило `:focus-visible` в начале файла. Гасить `outline`
   можно только полю ввода, у которого есть своя рамка. Новый кликабельный `div` или `span`
   проводите через `makeActivatable()`, иначе с клавиатуры до него не добраться.

## Про производительность

Полная перерисовка и расчёт дерева в браузере — сознательный размен. Он рассыплется на
десятках тысяч узлов, но переделывать это без явной просьбы не нужно. Заметил, что твоя
правка ухудшает картину, — скажи в отчёте, не переписывай архитектуру сам.

## Правила работы

- Тексты интерфейса — по-русски, идентификаторы и комментарии в коде — по-английски.
  Любой новый или изменённый русский текст веди через навык `ru-text`.
- Держись стиля соседнего кода: тот же уровень комментариев, те же приёмы рендера.
- В отчёте: что тронул, как проверить в браузере (какой экран, какие шаги),
  нужна ли правка `#view-help` или серверной стороны.
