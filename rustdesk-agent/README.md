# Постоянный агент RustDesk на управляемой машине

Ставится **на ту машину, к которой подключаются**, а не на сервер. Задача — убрать
ручной запуск `rustdesk-1.4.9-x86_64.AppImage`: после установки машина
регистрируется на `rd.spritelutsk.duckdns.org` с момента загрузки, окно RustDesk
на экране не нужно.

```bash
sudo ./setup-linux.sh --password 'постоянный-пароль'
# если .deb уже скачан:
sudo ./setup-linux.sh --password '...' --deb ./rustdesk-1.4.9-x86_64.deb
```

## Почему AppImage так не умеет

AppImage — это процесс пользовательского сеанса. Он живёт, пока открыт сеанс, и
исчезает при выходе или перезагрузке; ни автозапуска, ни доступа к экрану входа у
него нет. Пакет `.deb` ставит `/usr/bin/rustdesk` и юнит `rustdesk.service`,
который запускается от root на этапе загрузки — это и есть «работает без
запущенного RustDesk».

## Что делает скрипт

1. Ставит пакет RustDesk 1.4.9 (скачивает с GitHub, если не передан `--deb`).
2. Пишет конфигурацию сервера **в два конфига**: `/root/.config/rustdesk/` для
   службы и `~/.config/rustdesk/` для пользователя. Разъезд между ними — самая
   частая причина «клиент зелёный, а сервер его не видит»: окно настроек правит
   пользовательский конфиг, а регистрируется служба со своим.
3. Задаёт постоянный пароль (`rustdesk --password`), иначе входящий сеанс придётся
   подтверждать вручную на той стороне — то есть снова сидеть за машиной.
4. Включает и запускает `rustdesk.service`, показывает ID машины.

## Чего это не решает

- **Выключенную машину.** Агент нужен работающей ОС; для «разбудить» нужен
  Wake-on-LAN, это отдельная задача.
- **Wayland.** Захват экрана и экран входа надёжно работают на X11. Если сеанс
  на Wayland, в `/etc/gdm3/custom.conf` снять комментарий с `WaylandEnable=false`
  и перезагрузиться.
- **Windows-машину.** Там аналог — установить RustDesk обычным установщиком
  (не портативный `.exe`) и включить «Запускать при загрузке» плюс постоянный
  пароль. Конфиг службы лежит отдельно:
  `C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\RustDesk\config\RustDesk2.toml`.

## Проверка со стороны сервера

```bash
docker logs cortendesk --since 5m 2>&1 | grep -E "peer\.rs|rendezvous_server\.rs"
docker exec cortendesk php -r '$d=new PDO("sqlite:/data/rustdesk/db_v2.sqlite3");
  foreach($d->query("select id,info from peer") as $r) echo $r[0]," | ",$r[1],PHP_EOL;'
```

Строка `update_pk <ID>` означает, что агент зарегистрировался. Зелёный статус в
окне клиента этого **не** доказывает: с пустым `custom-rendezvous-server` RustDesk
регистрируется на публичных серверах и тоже горит зелёным.
