# CortenDesk Remote (Electron) — десктопный клиент для Windows

То же приложение, что и WPF-версия в `../winclient`, но на Electron: список
устройств из консоли CortenDesk с присутствием, поиском и фильтрами, а сеанс —
нативный веб-клиент CortenDesk в отдельном окне.

**Стек:** Electron 33, чистый JS без сборщика и фреймворков. Интерфейс русский,
светлая тема — та же палитра, что у веб-портала.

## Чем отличается от WPF-версии

Функционально — ничем, это осознанный порт один в один. Разница в устройстве:

| | WPF | Electron |
|---|---|---|
| Движок сеанса | WebView2 (нужен Runtime на машине) | Chromium внутри самого приложения |
| Размер дистрибутива | 1,3 МБ или 162 МБ | 269 МБ (папка) |
| Хранение токена | DPAPI через `ProtectedData` | `safeStorage` (на Windows это тот же DPAPI) |
| Сеть | `HttpClient` в приложении | `fetch` в main-процессе |
| Требования к ОС | .NET 8 Desktop Runtime + WebView2 | ничего |

Electron ничего не требует на машине оператора вообще — Chromium едет с
приложением. Платой за это идёт размер.

## Что оно делает и чего не делает

Делает: вход по учётной записи CortenDesk (`POST /api/login`), список устройств
(`GET /api/peers`) с индикатором «в сети», поиск по всем полям, фильтр по папке
(`/api/device-group/accessible`), фильтр «только в сети», сортировка по любому
столбцу, автообновление раз в 15 секунд, окно сеанса с F11 на весь экран,
контекстное меню строки (подключиться / копировать ID / открыть в браузере),
запоминание входа между запусками.

Не делает — и это осознанно: **не реализует протокол RustDesk сам**. Захват
экрана, пробивка NAT, VP8/VP9/H.264/AV1 и шифрование сеанса — это целиком
RustDesk. Приложение открывает готовый нативный веб-клиент CortenDesk, который
умеет и просмотр, и управление, и передачу файлов.

## Две авторизации — так и задумано

| Что | Чем авторизуется | Где живёт |
|---|---|---|
| Список устройств, папки | Bearer клиентского API (`/api/login`) | `%APPDATA%\cortendesk-remote-electron\token.dat`, шифр `safeStorage` |
| Страница сеанса `/webclient` | Обычная сессия консоли (middleware `auth`) | cookie в разделе `persist:cortendesk` |

Bearer в страницу консоли не подставить — это разные механизмы аутентификации
на стороне сервера. Поэтому первый сеанс на новой машине покажет форму входа
консоли (а на вашем сервере — сразу редирект на SSO портала: Caddy переписывает
голый `GET /login` в `/login/oidc`). Cookie живёт в persist-разделе сессии, так
что дальше вход не спрашивается.

Окно сеанса доводит дело до конца само: если после логина сервер увёл на главную
консоли, окно возвращается на `/webclient?id=…` — до трёх попыток, чтобы не
зациклиться.

## Безопасность рендерера

`contextIsolation: true`, `nodeIntegration: false`, у окна сеанса дополнительно
`sandbox: true`. Рендерер не видит ни файловой системы, ни сети — только
вызовы, перечисленные в `src/preload/preload.js`. Все запросы к API идут из
main-процесса; это ещё и обходит CORS, которого консоль произвольным источникам
не отдаёт. Данные с сервера вставляются исключительно через `textContent`.
В обоих HTML стоит CSP `default-src 'none'`.

Разрешения для окна веб-клиента выданы точечно: буфер обмена и полный экран,
всё остальное отклоняется.

## Сборка

```bash
npm install
npm run check        # синтаксическая проверка всех файлов
npm start            # запуск из исходников
npm run package:win  # сборка под Windows x64 -> dist/CortenDeskRemote-win32-x64
```

Собрано и проверено здесь на Node 22.14 / Electron 33.4.11: `npm run check`
проходит, пакет под win32-x64 собирается с Linux без wine.

Готовая сборка — `dist/CortenDeskRemote-win32-x64/`, запускать
`CortenDeskRemote.exe`. Это папка, а не один файл: так устроен Electron, рядом с
exe лежат Chromium и ресурсы. Исходники приложения — в `resources/app.asar`.

Две вещи, которых в этой сборке нет, потому что они требуют Windows или wine:
своя иконка и метаданные exe (имя издателя, версия в свойствах файла). Если
нужны — соберите `npm run package:win` на Windows, добавив `--icon=...`.
Установщик (NSIS/MSI) делается отдельно, например `electron-builder`.

## Про `npm audit`

`npm audit` показывает 3 high в цепочке `extract-zip` → `@electron/packager` /
`electron`. Это **инструменты сборки** в `devDependencies`: в собранное
приложение они не попадают (в `app.asar` только `src/` и `package.json`).
В рантайме у приложения зависимостей нет вообще.

## Особенности API, которые учтены в коде

Проверено запросами к работающему серверу:

- `POST /api/login` с неверным паролем отвечает **HTTP 200** и телом
  `{"error":"Wrong credentials"}` — по статус-коду ошибку не поймать, клиентский
  протокол RustDesk так устроен. `api.js` всегда смотрит в тело.
- `GET /api/peers` с негодным токеном — `401 {"message":"Unauthenticated."}`;
  это превращается в ошибку с флагом `expired`, сохранённый токен стирается,
  приложение просит войти заново.
- Списочные ответы страничные: `{"total": N, "data": [...]}`, `pageSize` не
  больше 500. Клиент докручивает страницы циклом.
