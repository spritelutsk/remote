# CortenDesk Remote — десктопный клиент для Windows

Приложение для удалённого управления рабочими столами: список устройств из
консоли CortenDesk с присутствием, поиском и фильтрами, а сам сеанс —
нативный веб-клиент CortenDesk во встроенном движке Edge WebView2, прямо
в окне приложения.

**Стек:** C# / .NET 8 / WPF + `Microsoft.Web.WebView2`. Интерфейс русский,
светлая тема — та же палитра, что у веб-портала.

## Что оно делает и чего не делает

Делает:

- вход по учётной записи CortenDesk (клиентский API `POST /api/login`);
- список устройств (`GET /api/peers`) с индикатором «в сети», ОС, владельцем,
  папкой и заметкой; поиск по всем полям, фильтр по папке, фильтр «только в сети»;
- автообновление присутствия каждые 15 секунд (сервер обновляет его примерно
  с тем же шагом — по heartbeat клиентов, чаще опрашивать бессмысленно);
- сеанс управления в отдельном окне со встроенным браузером, режим «во весь
  экран» по F11;
- контекстное меню: подключиться, скопировать ID, открыть в системном браузере;
- запоминание входа между запусками (токен шифруется DPAPI на текущего
  пользователя Windows).

Не делает — и это осознанно: **не реализует протокол RustDesk сам**. Захват
экрана, пробивка NAT, VP8/VP9/H.264/AV1 и шифрование сеанса — это целиком
RustDesk; писать их заново смысла нет. Приложение показывает уже готовый
нативный веб-клиент CortenDesk, который умеет и просмотр, и управление, и
передачу файлов.

## Две авторизации — так и задумано

Это единственное неочевидное место в архитектуре.

| Что | Чем авторизуется | Где живёт |
|---|---|---|
| Список устройств, папки | Bearer клиентского API (`/api/login`) | `%APPDATA%\CortenDeskRemote\token.dat`, шифр DPAPI |
| Страница сеанса `/webclient` | Обычная сессия консоли (middleware `auth`) | cookie в профиле WebView2 |

Bearer в страницу консоли не подставить — это разные механизмы аутентификации
на стороне сервера. Поэтому при первом сеансе на новой машине окно покажет
форму входа консоли (а на вашем сервере — сразу редирект на SSO портала, Caddy
переписывает голый `GET /login` в `/login/oidc`). Cookie сохраняется в
`%LOCALAPPDATA%\CortenDeskRemote\WebView2`, так что дальше вход не спрашивается.

`SessionWindow` умеет доводить дело до конца сам: если после логина сервер
увёл на главную консоли, окно возвращается на `/webclient?id=…` (до трёх
попыток, чтобы не зациклиться).

## Сборка

Проект собирается и на Linux — для проверки компиляции (`EnableWindowsTargeting`).
Собран и проверен здесь: **0 ошибок, 0 предупреждений**, .NET SDK 8.0.424.

```bash
dotnet build -c Release
```

Готовый self-contained .exe (не требует установленного .NET):

```bash
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Облегчённый вариант (нужен установленный .NET 8 Desktop Runtime):

```bash
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

`SelfContained` и `PublishSingleFile` намеренно **не** прописаны в `.csproj`:
там они притягивают RuntimeIdentifier хоста и ломают сборку везде, кроме Windows.
А вот `IncludeNativeLibrariesForSelfExtract` прописан — без него нативный
`WebView2Loader.dll` не попадает внутрь однофайлового .exe.

Обе сборки уже готовы:

| Файл | Размер | Что нужно на машине |
|---|---|---|
| `dist/self-contained/CortenDeskRemote.exe` | 162 МБ | ничего, .NET внутри |
| `dist/runtime-required/CortenDeskRemote.exe` | 1,3 МБ | [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0) (`winget install Microsoft.DotNet.DesktopRuntime.8`) |

WebView2 Runtime нужен обеим — см. ниже.

## Требования на машине оператора

- Windows 10 1809 или новее;
- **Microsoft Edge WebView2 Runtime** — есть в Windows 11 и везде, где стоит Edge.
  Если его нет, окно сеанса покажет объяснение и кнопку загрузки.

Клиент RustDesk на машине оператора **не нужен** — сеанс идёт через браузерный
движок. На управляемой машине он, разумеется, нужен: именно он даёт RustDesk ID.

## Настройка при первом запуске

Адрес сервера по умолчанию — `https://rd.spritelutsk.duckdns.org`; поле на
экране входа редактируется, схему можно не писать (`https://` подставится).
Логин и пароль — учётная запись консоли CortenDesk.

Двухфакторную аутентификацию клиентский API CortenDesk не поддерживает: если
она включена, приложение так и скажет и предложит войти через веб-консоль.

## Особенности API, которые учтены в коде

Проверено запросами к работающему серверу:

- `POST /api/login` с неверным паролем отвечает **HTTP 200** и телом
  `{"error":"Wrong credentials"}` — по статус-коду ошибку не поймать, клиентский
  протокол RustDesk так устроен. `CortenDeskClient` всегда смотрит в тело.
- `GET /api/peers` без токена — `401 {"message":"Unauthenticated."}`; это
  превращается в `AuthExpiredException`, сохранённый токен стирается, приложение
  просит войти заново.
- Списочные ответы страничные: `{"total": N, "data": [...]}`, `pageSize` не
  больше 500. Клиент докручивает страницы циклом.
- `GET /api/login-options` на этом сервере отдаёт SSO-провайдера
  «Войти через портал» — это OIDC портала `spritelutsk.duckdns.org`.
